# 01. Acceptance criteria and automatic NCRs

Spec `spec-quality-tolerance-ncr-001` · compatibility: behavior-compatible · leakage review: passed

## Summary

A per-project library of acceptance criteria carries numeric limits (a rule type, a nominal value, a lower limit and an upper limit, a unit label, plus descriptive and standards-reference text). Inspections, incoming-material reviews, lab-style test results, as-built survey records and hold/witness gates can each point at one criterion. Recording an outcome of fail, or of conditional acceptance, on an inspection, material review or test result automatically creates a linked non-conformance report that quotes the criterion and the measured value; a pass creates nothing. For as-built survey records the measured value is compared numerically against the criterion, and an out-of-tolerance record raises a non-conformance report when it is verified. Criterion limits are frozen once any record has been judged against them. Scoping facts: the criteria library is not attached to the lines of the inspection-and-test plan (those carry free-text acceptance wording only), and for ordinary inspections, material reviews and tests the pass/fail/conditional outcome is declared by the person recording it rather than computed from the numbers. Concrete field-length limits, page sizes and similar parameters are illustrative; the destination chooses its own values.

## Behaviour

- Each project has its own library of acceptance criteria. A criterion has a short code, a title, an optional description, an optional standards reference, optional discipline, category, characteristic and method text, an optional unit label, a rule type (one of: range, minimum, maximum, boolean, free text; default free text), an optional nominal value, an optional lower limit, an optional upper limit, an active flag (default active) and free-form supplementary data. The nominal value and both limits are held as short text rather than typed numbers so that free-text criteria and plain decimals can coexist; the destination may choose typed numerics (see open questions). _(q-bhv-01; observed)_
- Criteria can be listed per project with optional filters for category and for active state, using offset and limit paging with a default page size. _(q-bhv-02; observed)_
- Recording a result on an inspection takes an outcome of pass, fail or conditional, an optional measured value (short text), optional notes, an optional performed-at time and an optional severity for the report to be raised (critical, major, minor or observation). It is allowed only while the inspection is still open (draft, scheduled or in progress). The record stores outcome, measured value, notes, performed-at time and the acting user. _(q-bhv-03; observed)_
- Outcome mapping on an inspection: pass closes the inspection as passed and raises no report; fail closes it as failed and raises a report whose severity defaults to major; conditional closes it as passed (so any gate that depends on it is satisfied) but still raises a report whose severity defaults to observation. A caller-supplied severity overrides the default. _(q-bhv-04; observed)_
- The automatically raised report is created through the standard non-conformance creation capability with initial status identified. Its kind is material for incoming-material inspections and workmanship for every other inspection kind. It carries a title naming the inspection number and title (bounded length), the inspection location, a back-link to the inspection, and structured supplementary data recording the automatic source, inspection identity, outcome, criterion identity and measured value. The identifier of the created report is stored on the inspection. _(q-bhv-05; observed)_
- The description of an automatically raised inspection report states that it was raised automatically from the named inspection, repeats the inspection description and result notes when present, and, when the inspection references a criterion, appends a clause naming the criterion code and title, its standards reference when present, its tolerance (the nominal value, an inclusive lower bound and an inclusive upper bound, each shown only when non-empty) and the measured value when present. The description has a bounded length. _(q-bhv-06; observed)_
- Incoming-material review and lab-style test results use the same outcome grammar. Material review: pass sets accepted and raises nothing; fail sets rejected and raises a material report (default major); conditional sets accepted and raises a low-severity report (default observation). Test result recording: pass, fail and conditional all set the test to recorded; fail raises a report (default major) and conditional raises a report (default observation). A test linked to a material lot raises a material-kind report, otherwise a workmanship-kind report. These reports quote the criterion clause in the same way as inspection reports; material reports add certificate lapse, traceability (batch, heat, lot) and supplier details, and test reports add method, laboratory and sample details when known. _(q-bhv-07; observed)_
- A material may be reviewed only while it is draft, submitted or under review. A test result may be recorded only once, while it is still a draft. _(q-bhv-08; observed)_
- For as-built survey records the measured value is judged numerically against the criterion at survey time, yielding within tolerance, out of tolerance or not assessed. Verifying an out-of-tolerance record raises a workmanship report (default severity major, overridable) and stores its identifier on the as-built record. Detailed rules are in the as-built survey specification; this unit only records that the same criterion library feeds it. _(q-bhv-09; observed)_
- In the inspection register, completing a result by editing the status is refused: an inspection becomes passed or failed only through the result-recording action, which stores who performed it and raises the report a failure needs. Reopening a failed inspection for re-inspection by an ordinary edit is allowed and its earlier report stays on the register. _(q-bhv-10; observed)_
- Inspection-and-test plan control-point lines carry acceptance wording only as free text together with criteria text, frequency, method, a control-point type (hold, witness or review), a responsible role and a required signatory count. They have no numeric limits, and completing an inspection against such a line does not create a non-conformance report by itself. A failed or conditional hold/witness completion instead triggers a request for a formal disposition approval. _(q-bhv-11; observed)_
- A separate checklist-based inspection capability accepts a result of pass, fail or partial only through a complete action. A failed or partial completion signals a follow-up carrying the failed checklist items for punch-list creation; a pass signals closure evidence. No numeric limits and no non-conformance creation exist there. _(q-bhv-12; observed)_
- Shape of a criterion in terms of tolerance: it holds a standards reference (free text, bounded length), a rule type, a nominal value, and absolute lower and upper limits, plus a unit label (free text, bounded length). Tolerance is expressed as absolute lower and upper bounds, not as a separate plus-or-minus amount. The nominal value is descriptive only and takes no part in any comparison; it is just quoted in report text. A minimum rule uses only the lower limit, a maximum rule only the upper limit, a range rule both. Boolean and free-text rules have no numeric comparison. _(q-bhv-13; observed)_
- Exact within-tolerance rule (implemented only for as-built survey records): limits are inclusive at every boundary. Minimum: the value is within when it is greater than or equal to the lower limit. Maximum: within when less than or equal to the upper limit. Range: within when lower limit <= value <= upper limit. Anything else is out of tolerance. Values and limits are compared as exact decimals parsed from plain decimal text (optional sign, optional fraction; no locale-specific formats). No unit is carried by the measured value and no unit conversion of any kind exists: the criterion's unit label and any unit label stored on a test result or record are descriptive and never compared or converted, so the caller must supply the measured value in the unit the criterion's limits use. _(q-bhv-14; observed)_
- Information filled into an automatically raised report on a failed or conditional outcome: project; a title naming the kind of event (failed inspection, rejected or conditionally accepted material, failed test, or out-of-tolerance as-built), the record's number and title; a description carrying a statement that it was raised automatically from the named record, the record's own descriptive text and notes, kind-specific context (for materials: manufacturer and supplier, certificate type and number, certificate lapse, batch, heat and lot traceability; for tests: method, laboratory and its accreditation, sample identifier; for as-built records: capture method, instrument, accuracy class and value, deviation figure, verifier notes) and, if a criterion is linked, the criterion code, title, standards reference, the nominal value and lower and upper limits, and the measured value; a report kind (material or workmanship); a severity (supplied by the recorder or the default for the outcome); an initial status of identified; the location text where the source record has one; a link back to the source inspection where the source is an inspection; and structured supplementary data (automatic-source marker, source record identity and number, outcome, criterion identity, measured value, and for materials the certificate and traceability facts). The acting user is passed to the report creation capability (how it is stored there was not examined). The report number is assigned by the non-conformance capability's own per-project numbering. _(q-bhv-15; observed)_
- Retest flow: a failed inspection may be reopened by an ordinary edit (to draft, scheduled or in progress; its earlier report stays on the register and still points at it) and a new result then recorded. A new failing result raises a further report; a new passing result raises nothing. A test result is recorded only once, so a retest is a new test record (it may reference the same material lot or inspection); each failing test record raises its own report. The report itself closes only through its own workflow: identified, under review, corrective action, verification, closed (or void), where closing needs a recorded corrective action, must come from the verification state, and stamps the verifier. _(q-bhv-16; observed)_

## Inputs

- Criterion create and update inputs: code, title, description, standards reference, discipline, category, characteristic, method, unit label, rule type, nominal value, lower limit, upper limit, active flag, free-form supplementary data; each text input has a bounded length chosen by the destination. Update accepts any subset. _(q-in-01; observed)_
- An inspection is created with an inspection kind (incoming material, work, general inspection, hidden works or acceptance), a party authority level (default contractor quality control), an optional intervention-point class (hold, witness, surveillance, review), a title, optional description, location, activity reference, optional criterion reference, optional scheduled time and an optional element link. It starts as scheduled when a time is given and draft otherwise. _(q-in-02; observed)_
- The result action input is the outcome (pass, fail or conditional only), optional measured value, notes, performed-at time and optional severity. Any other outcome value is rejected at the edge. _(q-in-03; observed)_

## Outputs

- An inspection response exposes its number, kind, authority level, intervention point, title, location, criterion reference, status, outcome, measured value, result notes, the identifier of the report raised from it (empty when none), scheduled and performed times, the performer and resolved element links. _(q-out-01; observed)_
- A criterion response exposes every stored criterion attribute plus creator and timestamps; limits are returned as the stored text. _(q-out-02; observed)_

## States and transitions

- Inspection in the register: draft or scheduled or in progress may move to passed or failed only via the result action; passed and failed are then locked against deletion, and closed and void are locked against both deletion and editing. A passed or failed inspection may be reopened by an ordinary edit (this unfreezes its criterion). _(q-st-01; observed)_
- Criterion life cycle has no workflow states, only an active flag. A criterion can be switched to inactive so it stops being offered while the old records remain readable. _(q-st-02; observed)_

## Timing and ordering

- Within one result recording the outcome is stored first, then the report is created, then the report identifier is written back to the inspection so the response already shows it. _(q-ord-01; observed)_

## Edge cases

- Range-rule validation: when the rule type is range and both limits parse as plain decimal numbers and the lower limit exceeds the upper limit, creation is rejected with a plain-language message asking to swap them. Equal limits are accepted. Limits that are non-numeric or only partially supplied are accepted untouched. Minimum and maximum rules ignore ordering. On update the check is applied only when the same patch states the range rule and both limits. _(q-edge-01; observed)_
- A criterion with the free-text or boolean rule type, or with a missing relevant limit, cannot be evaluated numerically; its result for survey records is not assessed and is never silently treated as conforming. _(q-edge-02; observed)_
- Report descriptions omit the nominal, lower or upper part of the tolerance line when that value is empty; when no limits exist the clause ends after the criterion name and standards reference. _(q-edge-03; observed)_
- Missing criterion: an inspection, material review, test or as-built can be recorded with no criterion. Outcomes still apply and a failing outcome still raises a report, but the report text has no tolerance wording and, because the measured value is quoted only inside the criterion wording, the measured value then appears only in the report's structured supplementary data (for tests and inspections) and not in its description. For as-built records a missing criterion gives not-assessed. _(q-edge-05; observed)_
- Result with no unit or unit mismatch: the measured value is plain text with no unit of its own; it may be omitted, in which case the report omits the measured-value sentence. A test result has an optional unit label that is stored but not validated against the criterion's unit. A value with a unit suffix written in the text (for example with letters) cannot be parsed as a decimal and makes a survey result not-assessed. _(q-edge-06; observed)_
- Several results for one test subject: a test record holds exactly one outcome, recorded once. Several measurements of one test subject are therefore separate test records (a material lot or an inspection may have many test records; deletion of an inspection is refused while test records point at it). No aggregation, averaging, worst-case selection or combined verdict across records exists; each record is judged and raises its own report independently. For survey records, repeated survey of one as-built replaces the stored value while it is in the surveyed state. _(q-edge-07; observed)_
- Because the outcome can be recorded only once while a record is open, an inspection, material review or test cannot raise a second report for the same recorded result. _(q-edge-04; derived)_

## Errors

- Changing the rule type, unit label, nominal value, lower limit or upper limit of a criterion is refused with a conflict when any inspection, material record, test result or as-built record already references it. The message states how many records are judged against it and advises creating a new criterion and deactivating this one. Only real changes count: sending back the stored values together with other edits still saves the other fields. Descriptive text (title, description and similar) stays editable. _(q-err-01; observed)_
- Deleting a criterion is refused when any inspection, material record, test result, as-built record or hold gate references it; the refusal lists each kind of holder with its count and advises pointing those records at another criterion or clearing the active flag. An unreferenced criterion can be deleted. _(q-err-02; observed)_
- Referencing a criterion that does not exist and referencing one that belongs to a different project both return the same not-found answer, so the existence of foreign criteria is not revealed. _(q-err-03; observed)_
- Recording a result on an inspection that is not open returns a client error stating the current status. Setting passed or failed through an ordinary edit returns a conflict pointing to the result action. While a result stands, changing the inspection's criterion returns a conflict advising to reopen the inspection first. Editing a closed or void inspection is a client error. _(q-err-04; observed)_
- Deleting an inspection is refused (with the reason) once it carries a result or is closed or void, and while any test result, hold gate or non-conformance report still points at it. _(q-err-05; observed)_
- If the non-conformance creation capability cannot create the report, the result-recording operation itself fails rather than silently recording a failed outcome without a report. _(q-err-06; observed)_

## What it must not do

- For ordinary inspections, material reviews and test results, the measured value is stored and quoted but is not compared against the criterion's limits by the system; the outcome is whatever the recording user selects. _(q-neg-01; observed)_
- A pass outcome never creates a report. Inspection-and-test plan lines never carry numeric limits and never trigger a report automatically on a failed completion. _(q-neg-02; observed)_
- A retest has no automatic linkage to a previously raised report: a passing retest does not close, annotate or reference the earlier report, and no quality record checks that a passing retest exists before a report is closed. Report closure depends only on the report's own workflow. _(q-neg-03; observed)_

## Security

- Access tiers: reading criteria and inspections needs read-only access; creating and updating criteria and inspections and recording results (including those that raise reports) needs editor access; deleting criteria and inspections needs manager access. A read-only user cannot create criteria or inspections. _(q-sec-01; observed)_
- Every read or write is checked against project membership; a user from another tenant or project cannot read criteria or inspections, create records in a foreign project, link a foreign criterion or link a foreign model, and receives not-found. _(q-sec-02; observed)_

## Invariants

- A record that was judged against a criterion never sees that criterion's limits change underneath it, and the criterion cannot disappear while referenced. _(q-inv-01; observed)_
- Every fail or conditional outcome recorded on an inspection, material review or test result is accompanied by a linked report whose identifier is held on that record. _(q-inv-02; derived)_
- A completed result that has been recorded is evidence: it cannot be changed through ordinary edits or deleted. _(q-inv-03; observed)_

## Notes

- Limits are held as text so that free-text criteria and locale-neutral decimals coexist; numeric comparison, where done, uses exact decimal arithmetic on plain decimal strings only (no locale-specific number formats). A destination that stores typed numbers must preserve the same inclusive comparison and exact-decimal behavior. _(q-compat-01; observed)_

## Non-goals

- No implementation code, schemas, route paths, permission keys or event names are specified here.
- Detailed as-built tolerance rules, hold/witness gating and stake-out deviation maths are covered by their own units.
- Plan-line numeric tolerances are not specified because the reference behavior does not implement them.
- Do not reproduce origin provenance markers.

## Test cases

- **q-test-01**: Given a project with a range criterion with lower limit 10 and upper limit 20, When a client creates it, Then it is stored; and When a client creates another range criterion with lower 20 and upper 10, Then creation is rejected with a message to swap the limits.  
  Expected: First criterion saved; second rejected as invalid input; a range criterion with equal limits 15 and 15 is accepted; a range criterion with a non-numeric lower limit and upper limit 5 is accepted untouched.
- **q-test-02**: Given an open inspection of kind work linked to a maximum criterion with upper limit 50, When an editor records fail with measured value 60 and no severity, Then the inspection is failed and a report is raised.  
  Expected: Inspection status failed, outcome fail, measured value 60 stored; a workmanship report with severity major and initial status identified exists, linked back to the inspection, its description naming the criterion code and title, an inclusive upper bound of 50 and measured value 60; the inspection shows the report identifier.
- **q-test-03**: Given an open inspection, When an editor records pass, Then it is passed and no report exists for it.  
  Expected: Status passed, no report identifier on the inspection, no report created.
- **q-test-04**: Given an open incoming-material inspection, When conditional is recorded with severity minor, Then the inspection is passed and a material report with severity minor is raised.  
  Expected: Status passed; a report of kind material and severity minor exists (default would have been observation).
- **q-test-05**: Given an inspection already passed, When someone records a result or sets its status to failed through an ordinary edit, Then the attempt is refused.  
  Expected: Recording returns a client error naming the current status; the edit returns a conflict pointing to the result action; stored data is unchanged.
- **q-test-06**: Given a criterion referenced by one inspection, When an editor changes its upper limit, Then a conflict is returned; When the editor changes only its title, Then the save succeeds; When the editor re-sends the unchanged upper limit together with a new title, Then the save succeeds.  
  Expected: Limit change refused with a count of one judged record and advice to create a new criterion; title-only and unchanged-limit saves succeed.
- **q-test-07**: Given a criterion referenced by a test result, When a manager deletes it, Then deletion is refused listing the test result holder; When it is unreferenced, Then deletion succeeds.  
  Expected: Referenced criterion remains with refusal listing holder kind and count; unreferenced criterion removed.
- **q-test-08**: Given a draft test result tied to a material lot, When fail is recorded, Then the test becomes recorded and a material report with severity major is raised; When another record outcome attempt is made on the same test, Then it is refused.  
  Expected: Test status recorded with report identifier; second attempt returns a client error stating the test is no longer a draft.
- **q-test-09**: Given a submitted material record, When a reviewer records fail, Then the material is rejected and a material report with severity major is raised; When pass is recorded on another submitted material, Then it is accepted without a report.  
  Expected: Rejected plus report; accepted with no report.
- **q-test-10**: Given a user of another tenant, When they try to read a criterion, create an inspection in the foreign project, or reference a foreign criterion, Then every attempt returns not-found; Given a read-only user, When they try to create a criterion or an inspection, Then access is denied.  
  Expected: Not-found for foreign access; denial for read-only users.
- **q-test-11**: Given an inspection-and-test plan line of type hold whose free-text acceptance wording states a numeric limit, When an inspection against it is completed as failed, Then no non-conformance report is created automatically.  
  Expected: No report is created; only a disposition-approval request is raised for hold/witness lines.
- **q-test-13**: Given a range criterion with limits 10 and 20 and unit label millimetres, When as-built values 10, 20, 9.99 and 20.01 are surveyed on four records, Then the first two are within and the last two out of tolerance; When a record is surveyed with the text '15 mm', Then the result is not assessed.  
  Expected: Inclusive boundaries; unit text in the value defeats parsing; no unit conversion is attempted (a value of 0.015 supplied in metres against millimetre limits would be out of tolerance).
- **q-test-14**: Given a failed inspection that raised a report and was reopened, When a passing result is recorded, Then no new report is made and the earlier report is unchanged and still open; When instead a failing result is recorded again, Then a further report is raised.  
  Expected: A retest does not close or modify the earlier report; a repeated failure raises a further report (which identifier the inspection then exposes is an open question).
- **q-test-15**: Given a report raised from a failure and still in the identified state, When a user tries to close it directly, Then it is refused; When it has been moved through corrective action to verification with a corrective action text recorded, Then closing succeeds and stamps the verifier.  
  Expected: Closing only from verification with a corrective action; independent of any retest.
- **q-test-16**: Given an inspection with no criterion and measured value 7, When fail is recorded, Then a report is raised whose description has no tolerance wording and whose structured supplementary data holds the measured value 7.  
  Expected: Report exists; description lacks the criterion clause and measured sentence; supplementary data carries value 7.
- **q-test-17**: Given three test records for one material lot, two failing and one passing, Then two reports exist (one per failing record) and the lot has no combined verdict.  
  Expected: Independent judgment per record.
- **q-test-12**: Given an inspection with a result recorded, When a manager tries to delete it, Then deletion is refused; Given a draft inspection with no dependants, When a manager deletes it, Then it is removed.  
  Expected: Refusal for the evidenced inspection; removal of the draft.

## Open questions (decisions for QC Manager)

- Decision point: the requested capability describes numeric tolerances on inspection-plan lines with automatic report creation when a recorded result is out of tolerance. In the reference behavior, numeric limits live in a separate project criteria library and plan lines hold only free-text wording. Should the target attach a criterion (rule type, nominal, lower, upper, unit) to each plan line, or keep the split?
- Decision point: for ordinary inspections, material reviews and tests the reference behavior does not compute pass/fail from the measured value; the recorder chooses the outcome. Should the target compute the outcome from numeric limits when the criterion is numeric (as is done only for survey records), and what should happen when the recorder's chosen outcome disagrees with the computed one?
- Decision point: nominal and limits are held as short text, so any text can be saved for a range criterion if it is not a plain decimal. Should the target store numeric types and reject non-numeric limits for numeric rule types?
- Decision point: the tolerance wording in a report omits a limit only when its stored text is empty, so a limit of zero is displayed. The target should confirm that a zero limit (a legitimate bound) must still be shown.
- Decision point: conditional acceptance gives an inspection a passed status plus a low-severity report; whether a conditionally accepted inspection should keep dependent gates satisfied is a policy choice to confirm.
- Decision point: the report is raised in the same unit of work as the result write, but whether the earlier result write is rolled back when report creation fails was not independently verified; the target should define this as all-or-nothing.
- Decision point: the report severity vocabulary used by the automatic path is critical/major/minor/observation, while the manual non-conformance path in the plan-based quality area uses a different severity set; the target must pick one vocabulary or a mapping.
- Decision point: inspection references must be unambiguous across inspection sources. When more than one inspection capability numbers its inspections independently per project, a displayed inspection number alone may not identify a single inspection, and a report or gate that stores only a bare identifier cannot say which source it belongs to. The target should choose one inspection register, a source-qualified reference (kind plus identifier), or distinct number formats.
- Decision point: no unit handling exists. Should the target require a unit on measured values, validate it against the criterion's unit and convert between compatible units (for example millimetres and metres) before comparing?
- Decision point: nominal value is descriptive only; the target may want a nominal plus symmetric or asymmetric deviation form that derives the absolute limits.
- Decision point: closing a report does not require a passing retest, and a passing retest does not close or annotate the report. Should the target link retests to the report and require or offer closure on a passing retest?
- Decision point: when a recorded failure repeats after reopening, the reference behavior keeps only the most recent report identifier on the inspection (earlier reports remain but are no longer linked from it). The target should decide whether to keep the full history of reports per inspection.
- Decision point: tests with several measurements have no combined verdict; the target should decide whether a test can hold multiple readings and a rule such as all within, or an average.
- Not examined in depth (discovery lead): the front-end register and quality-concept screens; the stake-out and point-cloud deviation checks that also compare to numeric tolerances are covered by the as-built survey unit.
