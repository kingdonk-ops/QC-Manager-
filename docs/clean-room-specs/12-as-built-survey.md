# 12. As-built survey records

Spec `spec-as-built-survey-001` · compatibility: behavior-compatible · leakage review: passed

## Summary

Two related capabilities compare surveyed positions with design. (1) Stake-out: a request holds design stakes (planar east/north and optional height, optionally positioned on a road-like alignment by chainage and offset); each measured position is appended as a record that carries signed differences, a radial deviation in millimetres and a pass, fail or no-tolerance verdict against a tolerance snapshot taken from a profile; a failed stake may be turned into a non-conformance draft (manually, in bulk, or automatically when a project setting is on) or accepted as built with a reason; three validation rules report off-tolerance, untraceable and unresolved stakes. (2) As-built survey records: a captured value is compared with an acceptance criterion's numeric limits to give within, out-of-tolerance or not-assessed; the record moves through surveyed, verified and recorded; verifying an out-of-tolerance record raises a workmanship report; the legal-record attestation is a separate signed step. A deviation figure may also be imported from a point-cloud registration. Wider survey functions (control networks, coordinate-system handling, traverses, volumes, stockpiles) are neighbouring context only. Numeric limits such as row caps, preview sizes, text lengths and illustrative tolerance values are placeholders; the destination chooses its own values. Destination scope: only the as-built record register is planned for now; the stake-out capability and the point-cloud import are out of scope (see non_goals) and their claims are retained as background only.

## Behaviour

- Deviation maths for one measured stake: east difference and north difference are measured minus design, shown in millimetres rounded to 0.1 mm; the radial deviation is the planar distance between design and measured positions in millimetres rounded to 0.1 mm; the height difference is measured height minus design height in millimetres rounded to 0.1 mm, and exists only when both heights are known. Coordinates are in metres in the project coordinate system. The rounding precision is a behavioral parameter; a destination may choose its own as long as verdicts are free of floating-point noise. _(s-bhv-01; observed)_
- Verdict rule: if no horizontal tolerance is known the verdict is no-tolerance. Otherwise the stake passes when the radial deviation is at most the horizontal tolerance and, when the height difference, the vertical tolerance and both heights exist, the absolute height difference is at most the vertical tolerance; otherwise it fails. Limits are inclusive. Comparison uses the rounded values so floating-point noise never flips a verdict. The vertical check is skipped when any of its inputs is missing. _(s-bhv-02; observed)_
- Tolerance profiles map an item type to a horizontal and an optional vertical tolerance in millimetres, with a default row for item types the profile does not name; example item types are column, wall, pile, anchor bolt, kerb, centreline, grid line, boundary corner and other. A profile is one of: a built-in illustrative profile with placeholder tolerance values labelled as not a standard, a jurisdiction-specific profile offered only while that jurisdiction is enabled for the deployment, or a project-defined profile. Project-defined values must be greater than zero and not above a sensible upper bound chosen by the destination. Jurisdiction-specific values may carry a clause reference and a verified or to-verify status. No jurisdiction-specific tolerance values are bundled; the destination sources them from the applicable standards. _(s-bhv-03; observed)_
- A stake-out request snapshots the profile label, source, citation (standard, edition, clause and status) and the horizontal and vertical tolerance values at creation time, so editing or replacing a profile later never rewrites a verdict already given. A request may override either value on its own; changing the request's item type or profile re-resolves the snapshot. An unknown profile key is a validation failure. An empty key means no profile and therefore no verdicts. _(s-bhv-04; observed)_
- Measurement records are append-only. The newest record of a stake is the stake's current state and earlier records remain as history. Each record stores the measured position, the differences, the tolerance values in force, the verdict, instrument, control reference, measuring person, time and a note; instrument and control reference default to the request's. A request reports counts of stakes that are open (never measured), passed and failed by their latest record. _(s-bhv-05; observed)_
- Measured values can be imported from comma-separated text with point identifier, east and north required and optional height, instrument, control reference, measuring person and note. A row without identifier, east or north, or naming a stake that is not in the request, is reported as a problem with its line number and skipped; the response gives counts recorded, passed and failed plus the problems. An empty file is reported as a problem. The number of rows read is capped. _(s-bhv-06; observed)_
- Failed-stake follow-up: when a record fails, and the project setting for automatic drafts is on (default off), a non-conformance draft is created immediately; failure to create it never undoes the measurement. Otherwise a person may create a draft for one failed record or for all failed stakes. A draft is only for a record whose verdict is fail, only once per record, and not when the deviation was accepted. The bulk action covers the latest record of each failed stake and returns the drafts created and the number skipped because they already had a report or an accepted deviation. _(s-bhv-07; observed)_
- The draft non-conformance report for a failed stake is of workmanship kind with minor severity, titled with the stake identifier, the deviation and the tolerance (localised text). Its description lists the request code and name, design and measured coordinates to three decimals, the east, north, radial and height differences, the tolerances and profile label, the profile citation, and the measuring person, instrument and control reference. Its structured supplementary data marks it as a draft and records request, record, stake, deviations, tolerances and the validation rule that applies. When the plan position is within tolerance but the stake failed on height, the title and text quote the height difference against the vertical tolerance instead of the radial deviation. _(s-bhv-08; observed)_
- Accepting a deviation: only for a failed record, only once, with a required note of bounded length; it stores the accepting person's name, time and note and removes the stake from the unresolved-failure warning. It requires a separate survey-confirmation capability beyond ordinary write access. _(s-bhv-09; observed)_
- Three validation rules run over each stake's latest record: an error when a measured stake failed its tolerance (quoting the deviation and tolerance, using the height figures when the failure was in height); a warning when a measured record lacks instrument or control reference; a warning when a failed stake has neither a report nor an accepted deviation. Findings are returned in a stable order by rule with severity, message and suggestion, and with error, warning and info counts. _(s-bhv-10; observed)_
- Design import accepts a comma-separated stake list or an alignment exchange file used for road and landscape engineering. Preview returns rows read, a bounded preview of the first stakes with chainage and offset, the alignment and the problems found. Import in replace mode first removes unmeasured stakes; stakes whose identifier already exists are skipped; a file with neither stakes nor alignment is a validation failure; a stored alignment and the source file name are saved on the request. _(s-bhv-11; observed)_
- A stake can be added by hand by giving east and north, or a chainage (and optional offset) on the request's alignment. If only east and north are given and an alignment exists, chainage and offset are computed; a duplicate stake identifier in a request is a conflict; missing both position forms is a validation failure. Chainage grows along the alignment; offset is positive to the right of the direction of travel and negative to the left. A chainage outside the alignment, or a point lying beyond both ends, is a validation failure with a plain message. An alignment may consist of straights, circular arcs and linearly varying-curvature transitions. _(s-bhv-12; observed)_
- The printable stake-out sheet adds a grid-to-ground scale note computed at the stakes' centre; when grid and ground distance differ by at least a small threshold (illustratively 0.5 mm) over the reference distance, a warning finding about the difference is added to the sheet's findings. _(s-bhv-13; observed)_
- An as-built record has a title, discipline, location text, a capture method (laser scan, photogrammetry, total station, satellite positioning, tape, drone lidar, model extraction or manual; default manual), instrument, instrument calibration reference, accuracy class (survey, standard or coarse; default standard), accuracy value and unit, coordinate system label, survey date, surveyed-by, an optional acceptance criterion, a measured value, a source kind (point-cloud scan, point-cloud registration, take-off measurement, document, or manual), a source reference, a deviation-map reference and an optional element link. It gets a project-sequential record number and starts as draft. _(s-bhv-14; observed)_
- Recording a survey is allowed while the record is draft or surveyed (so a survey can be repeated). It takes optional measured value (otherwise the stored one is kept), deviation value, accuracy value and unit, survey date and notes; it sets status surveyed, stores the measured value and a computed tolerance result; and sets the surveyed-by field to the acting user if it was empty. No report is raised at this step. _(s-bhv-15; observed)_
- Tolerance result rule: with no criterion or a criterion whose rule is not minimum, maximum or range, the result is not-assessed. Otherwise the measured text must parse as a plain decimal or the result is not-assessed. Minimum: within if measured is at least the lower limit, else out of tolerance; a missing lower limit gives not-assessed. Maximum: within if measured is at most the upper limit; missing upper limit gives not-assessed. Range: within if the measured value lies between lower and upper limits inclusive; either limit missing gives not-assessed. Negative and decimal values are supported using exact decimal comparison. No unit conversion is performed; the measured value must already be in the unit of the criterion's limits. _(s-bhv-16; observed)_
- Verifying an as-built record is allowed only from surveyed. It sets verified. If the stored tolerance result is out-of-tolerance, a workmanship non-conformance report is raised (default severity major, overridable among critical, major and minor; an observation level maps to minor) with a description naming the record, its title, capture method, instrument and accuracy class and value, the deviation value, any verifier notes and the criterion clause; the report identifier is stored on the record. Verifying does not set the legal-record flag. _(s-bhv-17; observed)_
- Signing the legal-record attestation is allowed only from verified. Signing as valid sets the valid-for-legal-record flag, stores the signer, time (given or now), network address and a SHA-256 digest of a canonical snapshot of the record identity, capture, accuracy, criterion, measured value, tolerance result, validity decision and signer; and moves the record to recorded. Signing as not valid stores the same signature data but leaves the flag false and the status verified. Optional notes are kept. _(s-bhv-18; observed)_
- Out of scope for the destination (point-cloud import is not planned; see s-bhv-22 and non_goals) and retained as background only: importing an as-built from a point-cloud registration creates a draft with capture method laser scan, accuracy class survey, accuracy value equal to the registration's root-mean-square error in millimetres (when present), deviation value equal to the registration's count of out-of-tolerance points (a count, not a distance), the registration's deviation-map reference, source kind point-cloud registration, and supplementary data with scan, registration and coverage percentage; the registration's target is linked as an element when it resolves in the project, otherwise the record stays unlinked without failing. A registration or scan from another project is not-found. If the point-cloud analysis capability is unavailable in the deployment the import is a client error. _(s-bhv-19; observed)_
- Only the as-built check exists in the destination, with within, out of tolerance and not assessed results; no verdict unification with stake-out is needed. An out-of-tolerance as-built raises a major report on verification, and the severity can be overridden. The stake-out default does not apply because stake-out is out of scope. _(s-bhv-20; derived)_
- Reports are raised only on verification, never at survey time. The register can filter surveyed records that are out of tolerance, so such records remain discoverable before they are verified. _(s-bhv-21; derived)_
- The as-built deviation field holds a manual deviation distance only. Point-cloud import is out of scope, so no point counts are stored in that field. _(s-bhv-22; derived)_
- Units: no unit conversion is performed. The criterion's unit is shown for display, readings must be entered in that unit, and a value containing unit text is not assessed. _(s-bhv-23; derived)_

## Inputs

- Single measurement input: east, north, optional height, optional instrument and control reference, optional note. Request input: name (required, bounded length), item type (default other), profile key, optional per-request horizontal and vertical overrides (greater than zero, bounded above), optional element reference of cost-item, model or drawing kind, instrument, control reference and note. Settings input: a default profile key (validated when given) and the automatic-draft flag. _(s-in-01; observed)_
- As-built survey input is all optional (a survey may carry only notes when the value is already on the record); verify input has optional notes and optional severity; sign input has a validity flag (default true), optional notes and optional signing time. _(s-in-02; observed)_

## Outputs

- A stake response exposes identifier, design position, chainage, offset, code, a verdict of pass, fail, no-tolerance or open, the latest record and a record count. A request response exposes code, name, item type, profile snapshot, tolerance values, element link, alignment, instrument, control reference, source file, counts of stakes, open, passed and failed. A project summary exposes the number of requests and total open, passed, failed and draft-report counts. Deltas are exposed in millimetres to 0.1 mm. _(s-out-01; observed)_
- An as-built response exposes the record number, all captured attributes, measured and deviation values, the tolerance result, the valid-for-legal-record flag with signer, time, address and digest, source details, status, the raised report identifier and resolved element links. _(s-out-02; observed)_

## States and transitions

- As-built flow: draft to surveyed (survey action, repeatable while surveyed), surveyed to verified (verify action), verified to recorded (sign as valid), verified to superseded (ordinary edit), and void. An ordinary edit cannot set surveyed or verified, cannot move a verified or superseded record anywhere except verified to superseded, and recorded and void records cannot be edited at all. _(s-st-01; observed)_
- Stake state is derived: open until the first record, then the verdict of the latest record. A failed stake leaves the unresolved state when a report is attached to its latest record or its deviation is accepted. _(s-st-02; observed)_

## Timing and ordering

- Stakes are shown in the order they were added (design import order then manual additions); profile listings are shown with the built-in illustrative profile first, then enabled jurisdiction-specific profiles in a stable order, then project profiles. Every change writes an audit entry, and an audit failure never undoes the change. _(s-ord-01; observed)_

## Edge cases

- Boundary example: a radial deviation exactly equal to the tolerance passes; a deviation of 0.1 mm over fails. Height is ignored when the design or the measured height is absent or no vertical tolerance exists, so a stake can pass on plan alone. _(s-edge-01; derived)_
- A record taken with no tolerance in force is stored with the no-tolerance verdict and never triggers a draft report or a validation error. _(s-edge-02; derived)_
- A repeated measurement of the same stake supersedes the earlier one as the current state; a later pass hides an earlier fail from the counts but the failed record and its history remain. _(s-edge-03; derived)_
- Once a survey is recorded, the measured value and criterion of an as-built can change only through a new survey while surveyed, or not at all once verified or superseded (create a new record instead). A record may return to draft by edit only from the unjudged states. _(s-edge-04; observed)_

## Errors

- Stake-out errors: unknown profile, missing design in an import, duplicate stake identifier, missing position inputs, chainage outside alignment and absent alignment are validation or conflict failures; a draft report for a non-failed record, for one that already has a report, or whose deviation was accepted is a conflict; accepting a non-failed or already accepted deviation is a conflict; a request, stake or record that does not exist, or belongs to another project, is not-found. _(s-err-01; observed)_
- As-built errors: surveying a record that is not draft or surveyed, verifying a record not surveyed, and signing a record not verified are client errors naming the current status and the required step; setting surveyed or verified or changing the measured value or criterion in place after survey is a conflict; editing a recorded or void record is a client error; deleting is refused from verified onward; a criterion from another project is not-found. _(s-err-02; observed)_

## What it must not do

- An as-built that is undecidable numerically (no criterion, text or boolean rule, missing limit, non-numeric value) is never silently called conforming; it is reported as not-assessed and does not raise a report on verification. _(s-neg-01; observed)_
- The legal-record flag is never set automatically by survey or verification; only a deliberate signed attestation sets it. _(s-neg-02; observed)_

## Security

- Stake-out reading needs survey read access; writing (requests, design, measurements, settings, profiles, draft reports) needs survey write access; accepting a deviation needs an additional survey confirmation capability. As-built read is read-only level, create and update editor level, delete, verify and sign are manager level. All access is project scoped; foreign tenants and foreign criteria or elements give not-found; read-only users cannot create as-built records; editors can create and survey but not verify or sign. _(s-sec-01; observed)_
- The attestation digest is deterministic over a canonical, key-order-independent serialization and changes when any field such as the tolerance result changes; it is a 64-character hexadecimal string. _(s-sec-02; observed)_

## Invariants

- A stake's verdict always reflects the tolerance recorded on that same record; later profile edits never change earlier verdicts. _(s-inv-01; observed)_
- Each failed record has at most one report and at most one accepted deviation, and an accepted deviation never gets a report. _(s-inv-02; observed)_
- A verified or recorded as-built is never deleted or rewritten; corrections are made by superseding and creating a new record. _(s-inv-03; observed)_

## Notes

- Behavior example from illustrative sample data: two stakes on a straight axis with a placeholder 10 mm tolerance; the first measured within 5 mm radial and minus 2 mm height passes, the second measured at 15 mm radial fails, producing one draft report and a summary of one passed and one failed stake. Names and coordinates of any sample data are not part of the contract and must not be copied. _(s-compat-01; observed)_
- The attestation digest is SHA-256 over the destination's canonical JSON, the same helper used for inspection signatures. The exact snapshot content is not a compatibility requirement. _(s-compat-02; derived)_

## Non-goals

- No route paths, field names, rule identifiers, permission keys or exact messages are specified here.
- Control networks, coordinate-system conversion, traverse adjustment, volumes, stockpiles and mine survey features are context only and are not specified here.
- Point-cloud deviation analysis internals are out of scope; only the import into an as-built is specified.
- Stake-out is not in scope for now. The stake-out claims in this spec (design import, measurements, verdicts, drafts, validation, sheets, profiles and the related inputs, outputs and scenarios) are retained as background only and are not implemented in this slice; only the as-built check with within, out of tolerance and not assessed results exists, so no unification of verdict vocabularies is needed.
- Position-based deviation checks (chainage or offset, rotation or line slope, three-dimensional distance) belong to stake-out, which is not in scope for now; as-built records only compare a single measured value against a criterion.
- Tolerance profiles belong to stake-out, which is not in scope for now, so no jurisdiction-specific tolerance values are shipped.
- Wider survey functions, stake-out screens and point-cloud analysis are not in scope for now; only the as-built record register is planned.
- Do not reproduce origin provenance markers.

## Test cases

- **s-test-01**: Given a design stake at east 1000.000, north 2000.000 and a tolerance of 10 mm horizontal, When a measured position of east 1000.006 and north 1999.992 is recorded, Then the differences are 6.0 and -8.0 mm and the radial deviation is 10.0 mm.  
  Expected: Radial deviation 10.0 mm, exactly equal to the tolerance, so the verdict is pass.
- **s-test-02**: Given the same stake with design height 50.000 and a vertical tolerance of 10 mm, When the measured position is exact in plan but measured height is 50.015, Then the stake fails on height.  
  Expected: Radial deviation 0.0, height difference 15.0 mm, verdict fail; the follow-up text quotes the height difference against the vertical tolerance.
- **s-test-03**: Given a request with no profile selected, When any position is recorded, Then the verdict is no-tolerance and no draft report or validation error arises.  
  Expected: No-tolerance verdict; no findings of the off-tolerance rule.
- **s-test-04**: Given a request created with a profile of 10 mm and a stake already measured, When the profile is later changed to 5 mm, Then the earlier record keeps its verdict and tolerance; a new measurement of the same stake uses the request's current snapshot.  
  Expected: Old record unchanged; new record judged against the snapshot in force at that time.
- **s-test-05**: Given a stake that failed and a stake that passed, When a measured file with one fresh row for each is imported, Then each row creates a new record and the counts reflect recorded, passed and failed; a row for an unknown stake appears as a problem with its line number.  
  Expected: Counts recorded 2, passed and failed as computed, one problem for the unknown point; history for each stake has two records.
- **s-test-06**: Given a failed record and the automatic-draft setting off, When a person asks for drafts for all failed stakes twice, Then the first call creates one draft and the second creates none and reports one skipped.  
  Expected: One workmanship minor draft whose text quotes deviation, tolerance and profile citation; second call created 0 skipped 1; with the setting on the draft would have been created at measurement time.
- **s-test-07**: Given a failed record, When an engineer accepts the deviation with a note, Then the unresolved-failure warning clears; When a draft is requested afterwards, Then it is refused; When a second acceptance is attempted, Then it is refused.  
  Expected: Acceptance stored with person, time and note; later draft and second acceptance both conflict. A user with write access but without the confirmation capability cannot accept.
- **s-test-08**: Given a request with an alignment, When a stake is added by chainage 60 with offset 2 to the right, Then its east and north are computed; When east and north are given instead, Then chainage and offset are derived; When a chainage beyond the end is given, Then it is rejected.  
  Expected: Computed positions or derived chainage and offset; right offset positive; out-of-range chainage rejected with a plain message.
- **s-test-09**: Given a minimum criterion with lower limit 355, When as-built values 360, 355 and 320 are surveyed on three records, Then the results are within, within and out of tolerance.  
  Expected: within, within, out-of-tolerance.
- **s-test-10**: Given a maximum criterion with upper 50, a range criterion with limits 10 and 20, and another with -2.5 and 2.5, When values 50 and 60 (maximum), 10, 20, 21 and 9 (first range) and -1.25 and -3 (second range) are judged, Then 50 is within, 60 out, 10 and 20 within, 21 and 9 out, -1.25 within and -3 out.  
  Expected: Inclusive bounds on both ends; negative and decimal values handled.
- **s-test-11**: Given no criterion, a free-text criterion, a minimum criterion with no lower limit, or a measured value that is not a number, When a survey is recorded, Then the result is not assessed in every case.  
  Expected: not-assessed; verification raises no report.
- **s-test-12**: Given a surveyed record whose result is out of tolerance, When a manager verifies it with severity minor, Then it becomes verified and a workmanship report with severity minor is raised and linked; verifying a record in draft is refused.  
  Expected: Verified with report identifier; a draft record gets a client error telling to survey first.
- **s-test-13**: Given a verified record, When a manager signs as valid, Then it becomes recorded with the flag set and a digest; When it is later edited, Then the edit is refused; Given another verified record, When signing as not valid, Then it stays verified with the flag false.  
  Expected: Recorded and locked with digest present; declined attestation leaves verified and flag false; signing a record not yet verified is refused.
- **s-test-14**: Given an editor, When they create and survey an as-built, Then it succeeds; When they try to verify or sign, Then access is denied; Given a read-only user, When they create one, Then access is denied; Given a user from another tenant, When they read it or reference its criterion, Then not-found.  
  Expected: Permission matrix honoured.
- **s-test-15**: Given a draft as-built, When a client tries to set its status to verified by ordinary edit, Then a conflict is returned; Given a surveyed record, When a client changes its measured value by ordinary edit, Then a conflict is returned.  
  Expected: Conflicts explaining that the survey or verify action must be used.
- **s-test-16**: Out of scope for the destination, retained as background only. Given a point-cloud registration in the same project with error 3.2 mm and 7 out-of-tolerance points, When an as-built is imported from it, Then a draft laser-scan record with accuracy 3.2 mm and deviation value 7 and the map reference is created; When the registration belongs to another project, Then not-found.  
  Expected: Draft record as described; foreign registration gives not-found.
- **s-test-17**: Given two canonical snapshots with the same content in different key order, Then their digests are equal; Given snapshots differing in the tolerance result, Then the digests differ.  
  Expected: Equal digests for reordered keys, different for changed content, 64 hexadecimal characters.
- **s-test-18**: Given one measured failed stake with neither report nor acceptance, one measured stake lacking instrument, and one passed stake, When validation runs, Then it reports one error for the failed stake, one warning for the missing instrument and one warning for the unresolved failure, in a stable order by rule.  
  Expected: Counts error 1, warning 2; stable ordering by rule.
- **s-test-19**: Given a surveyed as-built that is out of tolerance, When it is verified with no severity, Then a report with severity major is raised and linked; Given another such record, When it is verified with severity critical, Then the report has severity critical.  
  Expected: Default major on verification; override honored.
- **s-test-20**: Given a record that has been surveyed and is out of tolerance but not yet verified, Then no report exists for it; When the register is filtered for surveyed records that are out of tolerance, Then the record is listed; When it is verified, Then the report is raised.  
  Expected: No report at survey time; filter finds the record; report appears on verification.
- **s-test-21**: Given a manual as-built survey with a deviation distance of 4.5 supplied, When it is stored and read back, Then the deviation field shows 4.5 as a distance; no point count is ever written to that field.  
  Expected: Deviation field holds the manual deviation distance only.
- **s-test-22**: Given a criterion with range limits 10 and 20 and unit label millimetres, When a record is created against it, Then the criterion's unit is shown for display; When a reading of 15 is surveyed, Then it is within; When a reading of '0.015 m' written with unit text is surveyed, Then the result is not assessed; no conversion is attempted.  
  Expected: Unit shown for display; unit text in the value gives not assessed; no conversion.
